# 执行效率

## 每轮的边界

先完成一批相互关联的实现与修正，再验证当前候选。区域开发时直接操作并检查已知设计要求，外部 Critic 对完整的本轮候选评分。一次反馈中的可执行问题集中修复，下一次评分使用修复后的当前截图。最终交付沿用当前有效评分。

## 材料与结果复用

- 新任务完整读取原规则。当前上下文保留已读版本和哈希，只补读变化内容及本阶段需要的参考。
- init 已提供项目 discovery，制作阶段沿用。doctor 用于安装或环境排查。已有风格、选定语言文档、同版本组件资料和生成素材按实际适用范围复用。
- design.md 维护完整风格原文与项目设计说明。style_summary、asset_plan 可以指向它。任务 JSON 保存执行字段，逐项 Markdown 从实际证据生成。
- scaffold 按实际 scope 和已声明适用项生成缺失文件。填写真实地址、断言、设计决定和观察，已有文件保留原样。
- cycle 复用源码、任务、策略、命令参数、日志与产物均匹配的成功命令；失败或失效时执行实际检查。构建在依赖它的浏览器之前运行，命令失败后先处理问题。
- 浏览器一次进程执行多个页面、状态和屏宽。同一真实操作可同时断言动态状态、按钮样式和相关行为。
- critic-run 完整核验最新评分、执行凭证、原始回复、截图和当前版本后复用该轮。高分与低分均保留原值，复用不新增模型请求，原有批准材料继续绑定原评审字节。
- finalize 一次完成清单同步、完整检查和交付复核绑定。取得适用签名后只运行 check 核验当前材料。

## 运行计划

scaffold 生成 work/frontend-policy/verification-run.json。commands 填各个已声明必需命令的 id 和 argv，使用当前项目的命令。browser_spec 指向实际用例，critic 为 true。执行以下命令完成本轮检查。

```sh
python <skill>/scripts/cycle.py --root <project>
```

返回 READY_FOR_REVIEW 后继续独立合规复查、最终复核与适用批准。最终状态由 finalize/check 计算。局部排查继续使用 run、browser-run、critic-run 等独立入口。

## 保持质量

分级按用户任务范围确定，范围内原要求完整执行。所有变化都会按现有指纹与凭证规则使对应检查失效。模板中的空白、BLOCKED 和待定适用性须填写实际事实。Critic 低分继续落实反馈，当前范围内已识别的可执行改进继续处理。验证受阻时保留具体原因与已有成果。

总耗时取决于页面范围、外部生成速度和实际修正次数。记录本次执行与复用情况，用实际数据判断提效效果。
