# 使用、维护与发布检查

## 用户使用方式

新任务明确说：`使用 frontend-workflow，按我的原规则制作这个页面。`

已有风格明确说：`使用 frontend-workflow，沿用已选的 B 风格，修改这个页面。`

只审计可以说：`使用 frontend-workflow，只检查这个页面，不修改。` 只读范围要保留；不要为了补证据改业务文件或重新生成方案。普通前端任务不自动加载本 Skill；原设计要求仍独立生效。

## 安装检查

```powershell
python '<skill>/scripts/verify.py' doctor
```

`doctor` 检查规则映射、入口、显式调用配置、Python/Node、浏览器程序语法、Playwright 位置及 Hook 定义，并单列当前代码是否有真实 CLI 生命周期凭证。安装 PASS 不代表 Hook 已获信任，也不代表业务验收。

## 发布回归

```powershell
python -X utf8 -m unittest discover -s '<skill>/scripts/engine/tests' -p 'test_*.py' -v
python '<skill>/scripts/verify.py' host-probe --cli '<实际安装的 codex.exe>'
```

测试包含正常对照和失败反例：原规则映射、组件库替代、语义完整文案与必要性记录、动态/生成文案、禁色、默认色板、Emoji、等宽区域、动效、背景/内容素材、模型误报、执行记录篡改、计划变化、声明冲突、Hook 退避，以及批次复用、过程变化与合并交付的反例。浏览器反例实际启动浏览器；不调用生图或生成模型，不宣称测试夹具是业务页面。

变更后的脚本、参考文件或原规则进入策略哈希，旧业务任务的凭证会失效。保留业务资料，重读要求，更新任务并重跑受影响检查；不要直接把旧结果的哈希改成新值。

维护时先备份本 Skill 和全局验证器。不要覆盖用户其他 Skill、AGENTS 内容或 Hook 定义。Hook 命令配置改动时，由宿主正常审阅；不要修改 trusted_hash 或使用绕过信任参数。恢复必须使用同一版本的 Skill、验证器及规则映射，保留现有业务文件。

## 正式使用的边界

- 可执行检查、设计判断、工具来源和宿主激活分开报告。
- 本地安装可以正式用于约束执行和阻止已覆盖的虚假通过；它不提供“永不出错”的保证。
- 布局意图、口语语气、默认组件是否足够定制、素材是否贴合，仍需实际视觉审查。机器候选命中需要修复或有依据的处理，不能删掉检查装作没发现。
- 独立模型复查减少同一上下文的遗漏，但没有受保护外部身份。视觉任务的总体 PASS 不由模型自填结论解锁。
- 同一系统用户能修改脚本和凭证；这不是权限隔离或防恶意篡改的系统。若确需该边界，另行配置受保护 CI/外部审批。本 Skill 不声称已经安装它们。
- CLI 生命周期、桌面设置、真实桌面业务任务的 Hook 执行是三个范围，不互相替代。
