# 交付前复核与持续改进

每次交付前重新对照用户要求和当前实现。检查实际页面、操作结果和证据，写下可核对的观察、修正与结果。

## 复核顺序

1. 核对原规则与 design.md 的当前版本，补读用户最新要求和变化段落。当前上下文已完整读取且文件哈希未变时直接对照已有内容；规则变化、上下文缺失或新任务时完整读取。逐条清单检查缺项、待做、失败、未验证和通用描述。
2. 查看当前实际界面及适用状态。检查参考中的关键组合、配色与材质、字体、信息密度、文案必要性、组件定制、素材角色和动态反馈。正文核对实际渲染字体、中英文混排、必要说明与控件的一致性。
3. 运行尚缺的适用检查，检查独立复查的发现。把已识别、可执行、属于本次需求的改进项写清位置、问题与预期结果。
   视觉交付按 critic.md 取得当前独立评分。低于 9 分时按具体反馈实际改进，重测后以新截图和固定提示在全新上下文重评，评分达标后继续完成适用的全部验收。
4. 修正实际实现，更新设计决定和相关计划，重跑受影响的检查并同步清单。再次查看当前界面，继续处理新发现的问题。
5. 当前范围内没有遗留的规则缺口、已知缺陷或已识别可执行改进项时，记录结束依据，再进入最终交付与适用的受保护批准。

评估改进时结合用户目标、当前任务和实际证据。保留已选风格与已确认需求。新增产品功能、重选品牌或扩大页面范围需要相应任务依据。工具或依赖确实受阻时记录缺口与原因，保留 FAIL 或 BLOCKED。

## 分级执行

L1 在本次修改范围执行简短复核和必要检查。L2/L3 正式实现将本轮观察与改进结果记录到 JSON，交由 finalize 合并执行最终复核绑定与交付检查。四图参考阶段继续直接展示并等待选型，正式制作阶段执行完整闭环。规范维护按本次文档与检查器变更进行复核。

## 可核对的复核记录

记录每轮 rules、quality、scope 三类观察。rules 对应规则与清单，quality 对应当前页面或实现质量，scope 说明本次范围和剩余问题。observed 写具体位置、实际观察和依据，evidence 指向当前检查记录、截图、日志或已同步清单。纯源码文件由实现位置字段登记。

```json
{
  "schema": 1,
  "rounds": [{
    "observations": [
      {"area": "rules", "observed": "填写实际清单覆盖、缺口及对应记录", "evidence": ["work/checklist-results.md"]},
      {"area": "quality", "observed": "填写当前页面的具体对照与实际操作结果", "evidence": ["本次浏览器截图的实际路径"]},
      {"area": "scope", "observed": "填写本次复查范围及实际剩余问题", "evidence": ["本次检查记录的实际路径"]}
    ],
    "improvements": []
  }],
  "remaining_improvements": [],
  "completion_reason": "填写当前范围内结束修正的具体依据"
}
```

上述文本说明字段含义，制作时写本次事实。发现问题后在 improvements 写 id、issue、status。open 表示待修，blocked 表示受阻，resolved 记录实际 action、implementation 文件和复测 evidence。同一问题跨轮次沿用 id，最终依据最新结果判断。remaining_improvements 列当前仍可执行的范围内改进项。

## 命令与版本绑定

当前版本已有完整有效 Critic 记录时直接复用；本轮实际检查与独立复查的观察集中用于最终改进复核。用 scaffold 生成缺少的结构，填写实际事实。按 efficiency.md 执行一批修正和一次验证，再进入本节收尾。

完成当前检查、独立复查和实际改进复核后执行。已有清单可直接查看；最终命令会同步当前结果。首次生成时可先用 checklist-sync 查看结果，后续交付无需固定重复这一命令。

```powershell
python '<skill>/scripts/verify.py' finalize --root '<项目>' --observations work/delivery-reflection.json
```

finalize 开始时先将 result.json 原子标记为待完成的 BLOCKED，再同步清单、执行一轮完整验证、绑定复核并核验受保护批准，最终原子保存计算结果。异常时保存实际原因，中断时保留待完成状态。收尾结束后再次核对磁盘任务，任务变化保留受阻。它复用这一轮的实际验证结果，随后核对新复核凭证和签名。最终复核子阶段为 READY、FAIL 或 BLOCKED，交付结果为 PASS、FAIL 或 BLOCKED。任务、规则、计划、源码、运行资源、执行证据、清单和独立材料继续完整绑定。已知问题继续修正，补齐真实缺口后重做受影响检查和本轮复核。

源码、规则、计划、证据或复核输入变化后重新执行最终复核。新一轮复核开始后写入待完成状态，输入或检查失败时保持受阻。READY 表示当前检查与复核记录达到本阶段条件，最终视觉交付仍按 visual-approval.md 执行。复核记录全文进入批准包和签名，自动检查核对执行与版本，具体审美和改进判断结合实际材料审核。

分步排查仍可使用 checklist-sync、delivery-review、check，普通交付使用一次 finalize。正式签名登记后只执行 check，避免重新生成复核记录使已批准材料失效。常规制作按实际发现持续修正，Stop 的两次额度用于交付状态冲突的自动补救。
