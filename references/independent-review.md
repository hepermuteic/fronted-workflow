# Separate-context review and host evidence

Use this for formal L2/L3 UI acceptance after actual browser execution. A local L1 text/style change does not force the separate-review pipeline. It does not replace the original rules, project brief or meaningful automated tests.

Critic 的截图美学盲评按 critic.md 执行，覆盖每次视觉实现交付。它单独使用截图和固定提示。此处的原始材料合规复查按既有范围进行，源码、需求和合规评论只提供给相应复查者，保持 Critic 的上下文隔离。Critic 达标后导出合规复查材料，其中保留其实际执行记录和固定提示供核对，具体合规结论继续对照真实页面及源码独立检查。

## Frozen inputs
Run `scripts/verify.py review-packet --root <project> --brief <actual-brief-path>`. This creates a manifest and copies actual code, original design requirements, raw brief, selected style and captured DOM/screenshots. Implementer PASS records, delivery notes and conversation are excluded. Packet creation is not review execution or UI approval. Include the actual selected reference via task.selected_reference when available. Missing original input or stale screenshots must be reported.

## Independent read-only reviewer
Request a distinct subagent with no inherited conversation (`fork_turns=none` when supported). Give it only REVIEW.md, manifest.json and the raw packet, not the implementer's verdict, suspected defects or expected answer. This workflow explicitly calls for this separate reviewer when available. Require it to actually inspect screenshots and relevant source, check packet/source identity, original and project requirements, and report specific failures plus unverified scope. Do not allow it to modify the business project. If separate-agent tooling is unavailable, record BLOCKED instead of writing the review yourself.

The reviewer includes packet_id and actual viewed files. Produce a structured JSON report: schema=1, packet_id, reviewer={kind:separate_model,id:<actual-agent-id>}, verdict=PASS/FAIL/BLOCKED, findings=[{requirement,location,observed,status,evidence:[<raw-packet-relative-file>]}], and limitations. Register task.independent_review={packet:<local-manifest-path>,report:<local-report-path>}. Known failures in a valid report propagate to the overall result; PASS cannot unlock overall visual acceptance. Validate the packet against the current project. Changed source invalidates the old review; refresh affected evidence and request the necessary fresh review. A report with a claimed reviewer name is not independently authenticated by the local checker. Separate model review reduces shared assumptions; it is not a protected external approval identity and cannot grant overall visual PASS.

Resolve independently found defects within authorized scope and repeat affected checks. For a read-only regression sample, preserve the project and keep its expected known failures as regression evidence; do not fix or publish it without authorization.

## Project-specific assertions
Before production coding, task.project_requirements lists the raw source path, unique id, expected condition, actual implementation paths and verification. L3 production cannot rely on global rules alone. For mode=visual_review, supply project:<id> observations with condition, implementation and current screenshot evidence. For mode=browser, specify page/width/state and the exact expected assertion object; the checker requires that actual assertion in a qualifying fixed-runner record.

Supported additional assertions: expect_css_number (fontSize/fontWeight/lineHeight/width/height, min/max), expect_area_ratio (basis=viewport/parent, measure=area/height/width, min/max), expect_in_viewport, expect_hidden. Thresholds come from this project's brief and documented design decisions, not a universal magic number. Use these to test auxiliary type, image prominence, first-screen content and error-state clearing where relevant. Passing geometry does not prove visual quality; text on gradients, real device keyboards, actual component provenance and other unavailable boundaries remain separate checks.

## Host lifecycle check
Inspect the actual desktop Hooks settings and distinguish enabled from executed. Run `scripts/verify.py host-probe --cli <installed-codex.exe>` for an operational lifecycle regression. It launches the installed Codex CLI with a deterministic localhost Responses fixture, makes no real model call, does not bypass hook trust, and creates one isolated temporary marker through the actual native apply_patch tool and records SessionStart/UserPromptSubmit/PostToolUse/Stop under the real CLI process lineage. It verifies that Stop actually blocks missing evidence and that retry limiting ends the attempt. The marker and probe workspace are retained as evidence and are scoped to that invocation, not ordinary frontend auto-activation. The actual CLI writes no business files.

CLI lifecycle evidence, desktop setting state and enforcement during a real desktop UI task are different coverage. Report them separately. Local files and process logs remain writable by the same OS user; protected CI or external approval is a separate security boundary. Never edit trusted_hash or use bypass flags to manufacture a trusted host state. If review is required by the host, finish the concrete changes and show the actual review item for the user's final decision.
